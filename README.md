# tieba-archiver

把贴吧帖子完整保存下来：每一层的文字、图片、动图、楼中楼都在。就算帖子或回复以后被删、被隐藏，你的存档还在。有网页版和电脑版两种用法：

- **网页版（推荐）**：适用于公开的、几百层以内的帖子。只需要一个免费的 GitHub 账号，无需服务器、无需安装软件（自动存档用的是 GitHub 每月送的 2000 分钟免费运行时间，每天检查一次通常一分钟内完成，个人使用绰绰有余）。存档保存在你自己的 GitHub 私有仓库中，每天自动更新，可直接在网页上阅读。
- **电脑版（Windows / Mac / Linux）**：适用于需要登录才能查看的帖子，或上千层、图片达数 GB 的大帖（这种帖子放在网页版里，下载到电脑时很慢甚至会失败）；不想用 GitHub 也可以用它。存档保存在本地，支持搜索、倒序和只看楼主。

两个可以一起用：小帖放网页版每天自动更新，大帖用电脑版保存。

## 网页版

1. 在 [tieba-archiver](https://github.com/jas-herb/tieba-archiver) 页面右上角点 **Use this template** → **Create a new repository**，起个名字，选 **Private**，然后创建。
2. 进入新仓库，点上方的 **Actions**。如果看到提示，点绿色按钮启用。
3. 左边选 **贴吧存档**，点右边的 **Run workflow**，在框里粘贴帖子链接（一次可以粘贴好几个，用空格隔开），再点 **Run workflow**。
   - 手机浏览器上：**Actions** 在顶部的 **More** 菜单里；**贴吧存档** 在 **All workflows** 列表里。
4. 等运行完成（第一次存档要等几分钟，帖子越长、图片越多越久；之后每天检查通常一分钟内完成），回到仓库首页：**首页就变成了你的存档列表，点帖子标题就能阅读**。每一页的顶部和底部都有跳转链接：跳到本页顶部/底部，或者直接跳到最新的楼层。（这份使用说明会改名为 `USAGE.md`，还在仓库里。）

之后默认每天北京时间早上 6 点自动检查一次，有新回复就补上。想存更多帖子？重复第 3 步，或者直接在网页上编辑仓库里的 `threads.txt`，一行一个链接。

> 运行中不要连续点 Run workflow：GitHub 只保留最后一次排队的，中间排队的会被取消。要加好几个帖子，请一次填在同一个框里。

**下载到电脑上看**：在仓库首页点 **Code** → **Download ZIP**，解压后打开 `archives` 文件夹，双击各个帖子文件夹里的 `index.html`。

## 电脑版

**Windows**（免安装）：

1. 到 [Releases](https://github.com/jas-herb/tieba-archiver/releases/latest) 下载 `tieba-archiver.exe`，放进一个新建的文件夹里（存档会保存在它旁边）。
2. 双击运行，按提示粘贴帖子链接（按 Ctrl+V 或点鼠标右键都能粘贴），回车。

> 如果弹出「Windows 已保护你的电脑」，点「更多信息」→「仍要运行」。这是因为这个 exe 没有购买数字签名；它是 GitHub 用本仓库的代码自动打包的（见 Actions 里的「打包 Windows 版」）。个别杀毒软件也可能误报。

**Mac / Linux**：先[下载工具的 ZIP](https://github.com/jas-herb/tieba-archiver/archive/refs/heads/main.zip) 并解压。打开「终端」，输入 `bash `（后面有一个空格），把解压出来的 `tieba.sh` 拖进窗口，按回车。第一次会自动准备运行环境（一两分钟），然后按提示粘贴帖子链接就行。

> 需要 Python **3.9 或更新的版本**（目前最高支持到 3.14）。提示没有 Python？Mac 上如果弹出安装「命令行开发者工具」的窗口，点「安装」，装好后再运行一次就行；也可以到 [python.org](https://www.python.org/downloads/) 安装 3.14。

存档保存在程序旁边的「贴吧存档」文件夹里，**双击里面的 `index.html` 就能看**。

**更新已存的帖子**：再运行一次，输入 `1` 就会把存过的帖子全部更新一遍：新回复会补上，已经下载过的图片不会重复下载。只更新某一个帖子，就再粘贴一次它的链接。

**只有自己看得到的帖子**：此时需要**登录账号**。问到「是不是只有你自己看得到」时回答 `y`，按屏幕上的步骤找到 BDUSS 并粘贴。粘贴时屏幕上不显示内容是正常的。

> ⚠️ BDUSS 相当于你的账号密码，**不要发给任何人**，也不要填到网页版里。本工具只在你自己电脑上使用它，不会保存。用完如果不放心，在浏览器里退出一次百度账号再重新登录，刚才复制的 BDUSS 就作废了。
>
> ⚠️ **登录风险提示**：本工具用的不是贴吧官方接口，登录后是以你的账号身份读取帖子。偶尔使用一般没问题，但不排除被贴吧判定为异常访问、要求验证，甚至限制账号的可能。请只在必要时登录，不要短时间内反复抓取；登录时最好关掉代理并用平时上网的网络，免得被当成异地登录。

## 发给别人看

存档里是别人发的帖子，所以**仓库请保持私有**。要发给别人，请生成 **PDF**：每 100 层一个文件，图片缩小过，手机上也能直接打开。

- **网页版**：运行「贴吧存档」时勾选「同时生成 PDF」，运行完成后，在那次运行页面底部的 **Artifacts** 里下载「PDF」（保留 3 天，请及时下载）。免费账号的附件空间只有约 500 MB，图片很多的帖子放不下，请用电脑版生成。
- **电脑版**：保存完帖子后，问到「要生成可以直接发给别人的 PDF 吗」时回答 `y`。PDF 生成在「贴吧存档」里的「tieba_帖子ID_PDF」文件夹中。帖子更新后想发最新的，再保存一次、重新生成即可。

> 电脑版生成 PDF 需要电脑上有 Chrome 或 Edge（Windows 自带 Edge），程序会在后台调用，不会打开窗口。都没有的话，程序会生成排好版的网页，用浏览器打开后选择「打印 → 存储为 PDF」即可。

## 常见问题

- **运行失败了？** 网页版：在 Actions 页面点进失败的那次运行，看是哪一步标红了。本地：Windows 到 [Releases](https://github.com/jas-herb/tieba-archiver/releases/latest) 下载最新的 exe；Mac / Linux 重新运行一次 `tieba.sh`。本工具用的不是贴吧官方接口，贴吧更新后可能会用不了。
- **为什么要当场下载图片？** 贴吧的图片链接大约两周后就会失效。
- **Mac / Linux 第一次准备环境很慢或失败？** `tieba.sh` 会自动改用国内镜像，失败的话检查网络后再运行一次。
- **已经被删掉的楼层能存下来吗？** 第一次保存之前就被删掉的存不下来，所以想保存就趁早；保存之后才被删的，会一直留在存档里。
- **整个原帖被删了怎么办？** 存档原样保留，页面顶部和存档索引里会标注「原帖已删除或隐藏」，之后照常每天检查，不会报错。
- **帖子特别长、图片特别多？** GitHub 每次上传不能超过 2 GB，网页版会把图片分批上传（每批不超过 900 MB），在同一次运行里接着下，一般一次就能存完；实在太多时，每次运行最多花 90 分钟下载图片，没下完的下次接着下，文字每次都是完整的。另外 GitHub 建议每个仓库不要超过 5 GB，要存很多图片帖的话，可以分几个仓库。
- **加进来的帖子显示「还没存到」？** 刚发的帖子在审核期间别人看不到（通常半小时内），工具也看不到，每次检查时都会再试，不用管它。一直这样的话，检查一下链接对不对；加错了就在网页上编辑 `threads.txt`，删掉那一行（或者在行首加 `#`）。停止跟踪某个帖子也是这样操作，已经存下的内容会保留。

保存下来的内容版权归原作者，公开分享前请先询问作者。

<details>
<summary>给熟悉命令行 / GitHub 的人</summary>

- 直接运行 `tieba_dump.py`（或 `bash tieba.sh`）不带参数是问答模式；带上帖子链接就是命令行模式，`tieba.sh` 接受同样的参数。支持 Python 3.9–3.14（3.9 会使用 aiotieba 4.6.1；aiotieba 目前只提供到 3.14 的安装包）。
- Windows 上也可以不用 exe：装 Python（勾选「Add python.exe to PATH」），在工具文件夹里运行 `py -m pip install -r requirements.txt`（下载慢可以加 `-i https://pypi.tuna.tsinghua.edu.cn/simple`），之后用 `py tieba_dump.py`。exe 也接受同样的命令行参数。
- `--update-all [文件夹]`：更新文件夹里已存的全部帖子（默认是程序旁边的「贴吧存档」），有登录才能看的帖子时加 `--login`。想让电脑定时自动更新，可以用系统的计划任务（Windows「任务计划程序」、Mac/Linux `cron`）定时运行 `tieba-archiver.exe --update-all` 或 `bash tieba.sh --update-all`。
- `tieba_dump.py` 的其他参数：`--login` 需要登录；`--no-images` 只保存文字（已经下载过的图片照样引用）；`--images-only` 不重新抓文字，只接着下载没下完的图片；`-o 文件夹` 指定输出位置。返回码：0 完成，1 出错，4 原帖看不到了（存档原样保留），5 图片没下完（到了 `TIEBA_MAX_MB` 体积上限），6 找不到帖子、也从没存过。完整数据在 `thread.json` 里：每个人只存昵称、等级、是否吧务，不存用户 ID、IP 属地等能追踪到账号的信息。重新抓取时会和已有存档合并：消失的楼层 / 楼中楼带上 `missing_since`（第一次发现看不到的时间）继续保留；万一内容被系统改动（比如折叠），旧版本存进 `earlier_versions`（相同的内容只存一次，最多 20 个）。一次少了很多楼层或楼中楼时，会再抓一次核对，两次都没看到才标记，免得把贴吧限流当成删除。存档读不出来、或者 `-o` 指向的文件夹里存的是别的帖子时，会拒绝覆盖。
- 已知限制：登录着保存的公开帖里，只有你自己看得到的回复（比如被系统隐藏、仅自己可见的），之后不登录更新时会被标成「已删除」（内容还在）。这种帖子请一直登录更新。
- `render.py 存档文件夹`：不重新抓取，只重新生成网页和 `thread.md`。长帖的 md 按楼层号自动分页（`thread.md` 是 1–100 楼，`thread_2.md` 是 101–200 楼……），免得 GitHub 网页上显示不出来。
- `topdf.py 存档文件夹`：生成 PDF（默认放在旁边的 `<文件夹名>_PDF/`，`-o` 指定位置）。`--page-size A4` 改纸张大小（默认 A5，适合手机阅读）；`--drop-deleted` 去掉已删除的内容（默认保留并标注）；环境变量 `TIEBA_BROWSER` 指定浏览器。
- 网页版的工作方式：`.github/workflows/archive.yml` 抓取 `threads.txt` 里列出的帖子，存到 `archives/tieba_<ID>/`，每个帖子抓完、内容有变化就提交一次，并更新首页 `README.md` 的存档列表（第一次运行时，原来的 `README.md` 改名为 `USAGE.md`）；原帖整个看不到了时存档原样保留、不算失败；还没存过、又找不到的帖子（比如还在审核中）不算失败，每次运行都会再试，还没存过的帖子排在最前面抓。`threads.txt` 每行认行首的帖子 ID（后面可以写备注），或者这一行里的帖子链接。图片按 `TIEBA_MAX_MB`（900 MB）分批提交推送，下载截止时间是 90 分钟（`TIEBA_DEADLINE`），没下完的下次接着下。推送时如果仓库在别处被改过，会先接上远程的改动再推。直接编辑 `threads.txt` 也可以增删帖子。要改每天运行的时间，修改文件里的 `cron`（用的是 UTC 时间，等于北京时间减 8 小时）。
- `.github/workflows/test.yml`：每次推送时用 Python 3.9、3.12 和 Windows 各跑一遍抓取、合并、页面生成和 PDF 的检查。它和 `exe.yml` 只在工具本身的仓库里运行，用模板创建的存档仓库里不会跑（免得访问贴吧、消耗额度）。
- `.github/workflows/exe.yml`：用 PyInstaller 打包 Windows 版 exe，打包后先用真实帖子测一遍。手动运行时在运行页面的 Artifacts 下载；推送 `v` 开头的标签（比如 `v0.1`）时自动发布到 Releases。
- 存档仓库里是别人发的帖子，**请不要公开它**。工具本身的仓库（jas-herb/tieba-archiver）不会运行存档。
- 更新工具：用模板创建的仓库不会自动跟着更新。想用新版，把[本仓库](https://github.com/jas-herb/tieba-archiver)最新的全部文件复制到你的仓库覆盖掉就行，除了 `archives/`、`threads.txt`、`README.md` 和 `USAGE.md`（`.github/` 文件夹也要复制）。
